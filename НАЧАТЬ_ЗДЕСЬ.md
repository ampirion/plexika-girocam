# Гирокам Cloudflare — публикация только через браузер

**Ничего не устанавливайте на компьютер. Node.js, Git и терминал на вашем ноутбуке не нужны. Предыдущую инструкцию с локальными командами больше не используем.** Cloudflare сам устанавливает инструменты в своей среде сборки и публикует проект из репозитория. Этот путь официально поддерживается Workers Builds. [1](https://developers.cloudflare.com/workers/get-started/dashboard/) [2](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/)

Нужны только аккаунты GitHub и Cloudflare, браузер и готовые файлы из архива. Существующий сайт videoferma не меняем: для сервера создаём отдельный репозиторий.

**Текущий редактор V13.30 ещё не подключается к этому relay.** Публикация сервера — отдельный этап для V13.31. Остальные ваши правки редактора остаются в работе, этот архив их не подменяет.

## 1. Создайте отдельный репозиторий GitHub

Откройте **https://github.com/new**.

- Название: **plexika-girocam**.
- Можно выбрать **Private**.
- Включите **Add a README file**, чтобы после создания сразу появилась кнопка добавления файлов.
- Нажмите **Create repository**.

В созданном репозитории нажмите **Add file → Upload files**.

Распакуйте архив `plexika-cloudflare-browser.zip`. Откройте вложенную папку `plexika-girocam`. Перетащите на страницу загрузки **её содержимое**, а не ZIP и не внешнюю папку целиком:

```text
package.json
wrangler.jsonc
src/
    worker.js
    phone.html
```

Можно также загрузить `.gitignore` и эту инструкцию; для запуска они не обязательны. Нажмите **Commit changes**.

Проверьте: `package.json` и `wrangler.jsonc` должны быть видны сразу на главной странице репозитория, а файлы `worker.js` и `phone.html` — внутри `src`.

Секретов в выданном архиве нет. Свой будущий PAIRING_KEY в репозиторий не загружайте.

## 2. Подключите репозиторий к Cloudflare

Если аккаунта нет, зарегистрируйтесь на **https://dash.cloudflare.com/sign-up** и подтвердите почту. Затем откройте **https://dash.cloudflare.com/**.

1. Откройте **Workers & Pages** — иногда этот раздел находится внутри **Compute & AI**.
2. Нажмите **Create application**.
3. Выберите импорт Git-репозитория / подключение **GitHub**. Название кнопки может быть **Import a repository**, **Continue with GitHub** или **Connect GitHub**.
4. Если открылась выдача разрешений GitHub, выберите **Only select repositories** и разрешите доступ только к **plexika-girocam**. Доступ к вашему videoferma для этого не нужен.
5. Выберите репозиторий **plexika-girocam**.

Нужен именно **Worker**, не статический Pages-сайт, не Upload assets и не drag-and-drop статического ZIP. Сервер использует Durable Objects, поэтому вариант «загрузить только HTML как сайт» его не заменяет.

Официальный путь создания Worker из репозитория: [1](https://developers.cloudflare.com/workers/get-started/dashboard/).

## 3. Настройки публикации

На экране настройки проекта:

| Поле | Значение |
|---|---|
| Project / Worker name | `plexika-girocam` |
| Production branch | `main` |
| Root directory | корень репозитория, обычно пусто или `/` |
| Build command | оставить пустым |
| Deploy command | оставить стандартное `npx wrangler deploy` |

**Deploy command — это поле на сайте Cloudflare. Вы НЕ запускаете эту команду у себя на ноутбуке.** Она выполняется на сервере сборки Cloudflare. Конфигурация и зависимости уже указаны в файлах проекта. [2](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/)

Не выбирайте Workers Paid. Покупать домен, VPS или переносить ваш сайт не требуется. Используем бесплатный адрес `workers.dev`.

Нажмите **Deploy** / **Save and Deploy** и дождитесь успешной сборки. Если произошла ошибка, пришлите текст ошибки без секретов — не меняйте наугад тариф или тип Durable Object.

Откройте предоставленный адрес `https://plexika-girocam.…workers.dev`. Пока секрет не задан, он сообщит об этом — это ожидаемо.

## 4. Задайте секрет тоже через браузер

Откройте созданный Worker:

**Settings → Variables and Secrets → Add**.

Укажите:

- **Type:** `Secret`, не обычный Text.
- **Variable name:** `PAIRING_KEY`.
- **Value:** новый случайный секрет длиной не менее 24 символов, лучше 32 и более. Можно сгенерировать его в своём менеджере паролей. Это не должен быть пароль от Cloudflare, почты или другого аккаунта.

Сохраните его у себя: в следующей версии редактора он будет нужен только на компьютере для создания сеансов. Нажмите **Deploy** / **Save and deploy**. Добавление секрета через Dashboard официально поддерживается. [3](https://developers.cloudflare.com/workers/configuration/secrets/)

**Важно:** это секрет среды выполнения Worker в разделе **Settings → Variables and Secrets**, а не только переменная сборки в **Build settings / Build variables**. Переменные сборки не доступны серверу после запуска. [2](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/)

Никаких ключей в исходные JS-файлы не вписывайте. Пароль Cloudflare, API-токены и PAIRING_KEY ассистенту не присылайте.

## 5. Проверьте

Обновите адрес Worker. Должно появиться **«Сервер готов»**.

Откройте `/health` на конце вашего реального адреса. Ожидаемый ответ:

```json
{"service":"Plexika Girocam relay","protocol":1,"ready":true}
```

После этого пришлите **только публичный адрес `https://…workers.dev`**, без секретов. Публичный адрес сам по себе не разрешает создавать сеансы без PAIRING_KEY.

Если сам адрес Worker не открывается у вашего провайдера, сначала нужна проверка его доступности — общий Wi-Fi не устраняет блокировку внешнего домена.

## Как будет работать гирокам

В V13.31 на компьютере один раз укажете адрес и свой секрет. Редактор создаст QR для телефонной страницы, которую уже обслуживает этот Worker. Телефон откроет QR, вы разрешите датчики, затем включите управление камерой и калибровку на компьютере.

Схема: **телефон → Cloudflare → редактор**. PeerJS, WebRTC, TURN и ручное копирование ответа телефона в этом пути не нужны. Общий Wi-Fi не обязателен. Старую телефонную страницу на GitHub менять для этого способа не требуется.

Сеанс действует два часа, допускает один компьютер и один телефон. Показания не записываются приложением на сервер. Однако они проходят через Cloudflare; WSS шифрует соединение до сервера, а не обеспечивает сквозное шифрование между устройствами.

## Бесплатность и ограничения

Используем **Workers Free** с SQLite Durable Objects. Это сервис с квотами, не безлимит и не гарантия доступности. Если интерфейс требует покупки платного тарифа, остановитесь и покажите экран без личных данных: платный тариф не является требованием этого проекта.

На Free Durable Objects при превышении квоты соответствующие операции завершаются ошибкой, суточный сброс — 00:00 UTC. Сборки Workers Builds тоже имеют отдельные квоты. Не включайте платные тарифы ради этой инструкции.

Тарифы и ограничения: https://developers.cloudflare.com/durable-objects/platform/pricing/ и https://developers.cloudflare.com/workers/ci-cd/builds/limits-and-pricing/.

## Что проверено

**Локально на нативном Cloudflare workerd:** SQLite Durable Object, создание и авторизация сеанса, CORS для локального HTML, два настоящих WebSocket-клиента, передача ориентации, подключение/отключение, запрет второго телефона, переподключение, отказ неверному пакету.

**Статически:** синтаксис исходников; в архиве нет секретов, node_modules или локальной базы. Браузерный путь сверён с официальной документацией Cloudflare.

**Не проверено:** публикация через ваш GitHub/Cloudflare, доступность публичного адреса у вашего провайдера, физический телефон и интеграция ещё не выпущенной V13.31. Локальные проверки не выдаются за проверку вашей публикации.
